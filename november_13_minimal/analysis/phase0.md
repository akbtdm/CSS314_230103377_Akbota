**Topology.** 10 physical = 10 logical cores, so P_phys = P_log = 10 and there is no SMT region; the ten cores are 4 performance + 6 efficiency cores, so the inflection analysed in Phase 2 is the 4 → 5 worker boundary. The cache line is 128 bytes. Cache sizes are per cluster: the generic keys (`hw.l1dcachesize` = 64 KB, `hw.l2cachesize` = 4 MB) describe the efficiency cluster; the performance cores have 128 KB L1d each and share a 16 MB L2, the efficiency cores 64 KB L1d each and a shared 4 MB L2. There is no `hw.l3cachesize` key (no classic L3; Apple's system-level cache is not exposed), and the 128 MB footprint of Phase 3A exceeds every on-chip cache anyway.

**Timer.** 10⁶ consecutive `perf_counter_ns()` calls cost 58.23 ns each on average; the smallest non-zero difference between consecutive reads was 41 ns, so the clock resolves ≈41 ns. Timing an empty function through `run_benchmark(warmup=2, runs=7)` gives a noise floor of 0.083 µs median (IQR 0.167 µs). The shortest timed region in this lab (a ≈0.6 ms slice copy) is four orders of magnitude above that, so timer cost is irrelevant; run-to-run scheduler/clock variation is the real noise, which is why medians and IQRs of 7 runs are reported.

**Process model.** CPython 3.13.5 with the GIL, start method `spawn`: all worker functions are top-level, all experiment code sits under `if __name__ == "__main__":`. Spawning is ≈35 ms for one worker and ≈80 ms for ten (measured with the `--quick` configuration, `results_quick/phase1.json`); it is included in the Phase 1 and Phase 4 wall times (fresh `mp.Process` workers per trial) and excluded from Phases 2 and 3B (persistent `mp.Pool` created outside the timed region). macOS rounds `SharedMemory` mappings up to the 16 KB page, so every buffer is sliced to its requested length before use.
