**Topology facts that shape every later phase.** `sysctl` reports 10 physical and 10 logical CPUs: the M4 has no SMT, so P_phys = P_log = 10 and the lab's "p > P_phys" hyper-threading region does not exist on this machine. The ten cores are heterogeneous instead: 4 performance cores (perflevel0) and 6 efficiency cores (perflevel1), so the inflection analysed in Phase 2 is the 4 → 5 worker boundary. The cache line is 128 bytes (`hw.cachelinesize`), which is why Phase 1 sweeps the slot separation up to 256 bytes. The cache sizes are per cluster: the generic keys `hw.l1dcachesize = 64 KB` and `hw.l2cachesize = 4 MB` describe the efficiency cluster (the minimum over all cores), while the performance cores have 128 KB of L1d each and share a 16 MB L2; the efficiency cores have 64 KB of L1d each and share a 4 MB L2. `hw.l3cachesize` does not exist: there is no L3 in the classic sense, and Apple's system-level cache is not exposed to `sysctl`. The 192 MB footprint used in Phase 3A exceeds every on-chip cache regardless.

**Timer calibration.** Two million back-to-back `time.perf_counter_ns()` reads cost 60.96 ns per call on average (loop overhead included) and the smallest non-zero difference between consecutive reads was 41 ns, so the usable resolution of the clock is ≈41 ns. Timing an empty Python function through `run_benchmark` gives a noise floor of 0.041 µs minimum, 0.083 µs median and 0.167 µs maximum. The shortest timed region anywhere in this lab is a ≈0.9 ms slice copy in Phase 3A, four orders of magnitude above the noise floor, so timer overhead never matters; what does matter is run-to-run variation from the OS scheduler and clock management, which is why medians and IQRs over 7 runs are reported everywhere.

**Interpreter and process model.** The interpreter is CPython 3.13.5 (Anaconda build) with the GIL enabled, so threads cannot run Python bytecode in parallel and every parallel kernel below uses `multiprocessing.Process` or `mp.Pool` workers that communicate through `multiprocessing.shared_memory`, `mp.Array`, `mp.Value` and `mp.Barrier`. The start method on macOS is `spawn`: each worker imports the task module afresh, so all worker functions are defined at module top level and all experiment code sits under `if __name__ == "__main__":`. Spawning is not free; Phase 1 quantifies it at ≈40 ms for one worker and ≈90 ms for ten. It is included in the Phase 1 and Phase 4 wall times (which spawn fresh processes per trial, as the specification's `fs_worker` design implies) and excluded from Phases 2 and 3B, which create a persistent `mp.Pool` outside the timed region. One macOS detail affected the implementation: `SharedMemory` rounds the mapping up to the 16 KB page size, so every buffer is sliced to its requested length before being filled or copied.

### Cache-line boundary identification and forensic explanation

**Cache-line boundary (Table 1A).** With all ten workers writing adjacent 8-byte words (stride 1, all slots inside one 128-byte line) the sweep takes 501.09 ms (47.9 Mops/s). Moving the slots 16 bytes apart changes almost nothing (494.97 ms, −1.2 %). The largest single step is between 16 and 32 bytes of separation (−5.1 %, to 469.90 ms), a smaller step follows at 64 bytes (−1.9 %, 460.80 ms), and from 64 bytes onward the curve is flat: 128 bytes (463.93 ms) and 256 bytes (464.01 ms) are indistinguishable from 64 bytes within the run-to-run IQR of 6–16 ms. The total false-sharing penalty between the worst (8 B) and the plateau (64 B) is 40.3 ms, i.e. 8.7 % of the runtime, or 47.9 → 52.1 Mops/s.

So the empirically observed contention boundary on this M4 is at **≤ 64 bytes of separation**, not at the 128-byte line that `hw.cachelinesize` reports and that the audit guide expects for Apple Silicon. Two readings are consistent with the data: (a) the store path tracks ownership at a 64-byte granularity (half of the reported line), so one writer per 64-byte sector already removes the contention; or (b) the residual difference between two writers per 128-byte line (stride 8) and one writer per line (stride 16) is only ≈3 ms and sits below the resolution of this measurement (IQR 6–13 ms). The penalty clearly scales with the number of writers per line: 10 writers/line → 501 ms, 8 → 495 ms, 4 → 470 ms, 2 → 461 ms, 1 → 464 ms.

**Why the effect is only ≈9 %.** At p = 1 the loop costs 2314 ms for 2.4 × 10⁷ steps, i.e. 96 ns per read-modify-write step on a performance core. Almost all of that time is interpreter work on private objects (`acc * mult`, `+ (i | 1)`, `& mask`, the `ctypes` `__setitem__` conversion); only one 8-byte store per step reaches the shared line. A coherence miss that costs tens of nanoseconds is therefore issued only once every ~100 ns and is largely absorbed by the store buffer and out-of-order execution, so only a fraction of it surfaces as wall-clock time. In a compiled language the same loop would issue a store every few nanoseconds and the invalidation storm would dominate; in pure Python the interpreter is the bottleneck and the cache-coherence cost is a second-order effect.

**Karp-Flatt trajectories (Table 1B).** The experimental serial fraction rises with p under both layouts, but faster under false sharing:

| p | e(p), stride = 1 | e(p), stride = 16 | difference |
|---|---|---|---|
| 2 | 0.0376 | 0.0338 | 0.0038 |
| 4 | 0.0561 | 0.0529 | 0.0032 |
| 8 | 0.1303 | 0.1065 | 0.0238 |
| 10 | 0.1521 | 0.1153 | 0.0368 |

Three mechanisms are visible in these numbers:

1. *Process spawn/join overhead is a fixed serial cost.* A separate run of the same script with M reduced 100× (`results_quick/phase1.json`) measured 60.4 ms at p = 1 and 93.7 ms at p = 10 while the compute part was only ≈23 ms and ≈2 ms respectively, so starting and joining the `spawn`-mode workers costs ≈40 ms for one process and ≈90 ms for ten. At p = 10 that is already ≈19 % of the 472 ms wall time, which Karp-Flatt reports as serial fraction. This is why e(p) is non-zero and growing even at stride 16.
2. *Heterogeneous cores make the slowest worker the critical path.* With equal static partitioning (M/p per worker) the fifth and later workers land on efficiency cores, which finish last. e(p) jumps from 0.053 at p = 4 (all workers on performance cores) to 0.107 at p = 8 under stride 16, although no shared data is touched. Speedup saturates at 4.9 on ten cores (E₁₀ = 0.49) for the isolated layout.
3. *Cache-line contention adds on top of that under stride 1.* Up to p = 4 the two layouts differ by ≤0.004 (≤0.8 % in runtime) because four writers on one line, each storing once per ~100 ns, are still absorbed. From p = 8 the extra coherence traffic becomes visible: stride 1 is 9.5 % slower at p = 8 and 16.1 % slower at p = 10 (548.07 vs 471.91 ms), and e(p) ends 0.037 higher. The sharp rise of e(p) under stride 1 is therefore the sum of a growing straggler effect (E-cores) and a contention term that grows with the number of writers per line.

Note on measurement drift: the stride-1 point at p = 10 was measured twice, as 501 ms in the stride sweep and 548 ms in the scaling sweep two minutes later. The 9 % gap between two medians of seven runs each is the honest noise level of this laptop (background activity, clock management under sustained load) and should be kept in mind when reading differences of a few percent in Table 1A.

### Amdahl ceiling and core-heterogeneity inflection analysis

**Serial fraction and Amdahl ceiling.** At p = 1 Stage A takes 15.2 ms of the 1090.58 ms trial, so the measured serial fraction is s = 0.0139. Amdahl's law then predicts S∞ = 1/s = 71.8 and S(P_log = 10) = 1 / (0.0139 + 0.9861/10) = 8.89 (E₁₀ = 0.89). The observed strong-scaling speedup at p = 10 is 4.58 (E₁₀ = 0.46), i.e. only 52 % of the Amdahl prediction. Amdahl's bound is not violated; it is simply far away, because its only assumption about the hardware is "p identical workers", and the M4 is not ten identical cores.

**Performance/efficiency-core inflection.** The CPU has no SMT (P_phys = P_log = 10), so the boundary the lab asks about is the one between the 4 performance cores and the 6 efficiency cores. The marginal speedup per added worker (ΔS = S_p − S_{p−1}) makes it obvious:

| added worker p | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| marginal ΔS | 0.923 | 0.789 | 0.557 | 0.186 | 0.296 | 0.185 | 0.286 | 0.245 | 0.118 |

Across the boundary p = 4 → 5 the marginal speedup drops from 0.557 to 0.186, a **−66.6 %** change for one added worker. Averaged over the two regimes, workers 2–4 add 0.756 of a core each, workers 5–10 add 0.219 each (−71 %). Expressed as capacity: going from 4 to 10 workers only shortens the trial from 333.69 ms to 237.92 ms (×1.40), so the six efficiency cores together contribute about 1.6 performance-core equivalents for this kernel, ≈0.27 of a P-core each (this includes any clock reduction the P-cores suffer when all ten cores are busy). Parallel efficiency falls from 0.82 at p = 4 to 0.69 at p = 5 and 0.46 at p = 10. The 4-worker point is also where the Amdahl curve and the measurement start to diverge sharply (3.84 predicted vs 3.27 observed; the gap is only 0.05 at p = 2).

The per-worker telemetry of Phase 3A shows the same thing from another angle: with ten barrier-synchronised FMA workers every process achieved 0.12–0.15 GFLOP/s, with no bimodal split into "fast" and "slow" workers, so macOS time-slices and migrates the processes across both clusters rather than pinning six of them to efficiency cores. Static equal partitioning therefore does not produce a single visible straggler, but the aggregate throughput of the machine still grows by only ≈0.2 core-equivalents per added worker beyond four.

**Weak scaling (Gustafson).** With N(p) = p × 250 000 the work per worker is constant, yet the trial grows from 170.80 ms (p = 1) to 351.01 ms (p = 10): weak-scaling efficiency drops to E_weak,10 = 0.487. Two components grow: Stage A, which is serial in the parent and proportional to N(p), goes from 2.39 ms to 27.37 ms (α rises from 0.0140 to 0.0780), and Stage B itself goes from 168.19 ms to 323.64 ms although every worker processes exactly 250 000 elements, again because the fifth and later workers run on slower cores and all ten share the package power budget. The Gustafson scaled speedup computed from α alone is S_G(10) = 10 − 0.078 × 9 = 9.30, which looks almost ideal. The contrast between S_G = 9.30 and E_weak = 0.49 is the real lesson of Experiment 2B: Gustafson's formula only accounts for the serial fraction and assumes that the parallel part keeps the same per-worker time at any p, which is false on a heterogeneous, power-limited laptop CPU. Both laws describe the software; the ceiling that actually binds here is the hardware topology.

### Roofline and cache-capacity analysis

**Hardware ceilings (Part 3A).** Ten worker processes each copying a 9.6 MB slice of a 96 MB shared buffer into a second 96 MB buffer took a median of 1.006 ms per slice copy. The lab's formula, BW = 2 × 96 × 10⁶ B / T_median, gives **BW_sustained = 190.81 GB/s**. That number should be read with care: it assumes all ten slice copies happen simultaneously inside one median worker time, but the per-worker times range from 0.83 to 2.3 ms and the whole block of 9 repetitions × 10 workers took 19.8 ms of wall time instead of 9 × 1.0 ms. Dividing the total traffic actually moved (90 copies × 2 × 9.6 MB = 1.73 GB) by that wall time gives **87.2 GB/s** (87–91 GB/s over the three rounds). The M4's LPDDR5X memory interface cannot exceed ≈120 GB/s, so the wall-clock figure is the physically meaningful sustained DRAM bandwidth and the lab-formula figure over-counts by roughly 2× because the copies only partly overlap. Both are reported; the 192 MB footprint guarantees that the traffic really goes to DRAM.

The compute ceiling is **P_sustained = 1.3309 GFLOP/s** for ten barrier-synchronised processes running the 16-way unrolled `x = x * a + b` loop (8 × 10⁷ FLOPs each), with per-worker rates between 0.129 and 0.158 GFLOP/s. One multiply-add statement therefore costs ≈15 ns, which is simply the cost of dispatching its ~5 bytecodes in CPython; the floating-point units of the M4 are idle most of the time. This "roof" is a ceiling of the interpreter, not of the silicon. The ridge point follows as **I\* = P_sustained / BW_sustained = 1.3309 / 190.81 = 0.0070 FLOP/Byte** (0.0153 FLOP/Byte with the wall-clock bandwidth). Any kernel whose operational intensity exceeds ≈0.01 FLOP/Byte is compute-bound on this platform in pure Python, i.e. every realistic kernel, including the naive GEMM at 0.125 FLOP/Byte.

**GEMM sweep and cache capacity (Part 3B).** All three variants produce bit-identical results (max|C(V1) − C(V2)| = 0, max|C(V3) − C(V2)| = 0, because all of them accumulate the k-sum in the same order). Performance: V1 (i-j-k) 0.1956 GFLOP/s, V2 (i-k-j) 0.4221 GFLOP/s, V3 (blocked) from 0.1738 GFLOP/s at BS = 4 rising monotonically to 0.2632 at BS = 48 and then flat: 0.2629 (64), 0.2624 (96), 0.2655 (128). The nominal optimum is **BS\* = 128** (0.2655 GFLOP/s), but everything from BS = 48 upward lies within 1.2 % of it while the IQRs are 1–5 % of the medians, so the honest statement is that the curve saturates at BS ≥ 48.

The tile working set W(BS) = 3 × BS² × 8 B is 384 B (BS 4), 6 KB (16), 24.6 KB (32), 55.3 KB (48), 98.3 KB (64), 221 KB (96) and 393 KB (128). Cache-capacity reasoning would predict the optimum where the tile just fits in L1d: BS ≈ 48 for the efficiency cores' 64 KB and BS ≈ 64 for the performance cores' 128 KB, with a drop once the tile spills into L2. The measured curve does reach its plateau at exactly those sizes, but it never drops: BS = 96 and 128 (221–393 KB, far beyond any L1d but inside the 4 MB / 16 MB L2) are as fast as BS = 48. The 393 KB tile of BS\* = 128 therefore fits "cleanly" only in L2, not in L1d. The reason is that the micro-kernel's inner statement `c_local[c_off + j] += a_ik * B[b_off + j]` costs ≈100 ns of interpreter time per iteration, which hides an L2 hit (a few nanoseconds) and even a DRAM access completely, and the row-wise traversal of B is sequential so the hardware prefetcher keeps the lines coming. What the sweep actually measures is **loop overhead**: at BS = 4 every inner `for j` loop runs only four iterations before paying the `range()` setup, the `a_ik` load and the `b_off`/`c_off` arithmetic again, and the three block loops add their own iterations; growing BS amortises that fixed cost, which is why throughput rises by 53 % from BS = 4 to BS = 48 and then stops improving once the per-loop overhead is negligible.

The ranking V2 > V3 > V1 confirms the same picture. V2 beats the best blocked variant by 1.59× because its inner loop indexes two local lists with a single index (`c_row[j] += a_ik * b_row[j]`) while V3 must compute `c_off + j` and `b_off + j`, two extra integer additions per multiply-add, plus the block-loop bookkeeping. V1 is 2.16× slower than V2 mainly because its inner loop recomputes `i * n + k` and `k * n + j` (four extra bytecodes per iteration); its stride-N walk through B does touch a new cache line per element, but the 384 lines involved (48 KB) still fit in L1d, so the cache effect is secondary to the interpreter cost.

**Roofline mapping.** With I\* ≈ 0.007 FLOP/Byte every variant sits on the flat compute roof: attainable = min(P_sustained, I × BW_sustained) = P_sustained = 1.3309 GFLOP/s for I_naive ≈ 0.125 FLOP/Byte (V1, V2) as well as for I_tiled(BS\* = 128) = 128/12 ≈ 10.67 FLOP/Byte (V3). Achieved fractions of attainable performance: **V1 14.7 %, V2 31.7 %, V3(BS\*) 19.9 %**. Even the naive kernel's memory-roof limit, 0.125 × 190.81 = 23.9 GFLOP/s, is 18× above the interpreter ceiling, so the memory system is never the bottleneck here. The conclusion of Phase 3 is that cache blocking, the classic optimisation for compiled GEMM, is invisible in pure Python: the lever that works is reducing the number of bytecodes per multiply-add (hoisting, unit-stride row slices, local lists), which is exactly what V2 does and why it is the fastest pure-Python variant; the next step up would be leaving the interpreter (array-level or compiled kernels), not tuning tile sizes.

### Chunk-size trade-off analysis

**Load imbalance of the static schedules.** The workload is triangular: item i costs K(i) = 1 + ⌊(i/60)²⌋ iterations, so the amount of work in a contiguous range grows with the cube of its upper bound. Under block-static partitioning worker t gets items [1200t, 1200(t+1)) and therefore the share ((t+1)³ − t³)/1000 of the total work: 0.1 % for worker 0 and 27.1 % for worker 9. The telemetry matches: worker 0 is active for 7 ms, worker 9 for 2089 ms, and the imbalance factor is λ = 2.455 (the pure arithmetic value would be 0.271 / 0.100 = 2.71; the measured value is lower because once the nine light workers have exited, the last worker runs alone on an idle performance core at full clock). Wall time is 2172.8 ms although the total active time of all workers is only ≈7.5 s, i.e. the machine is idle most of the time. Cyclic (round-robin) assignment interleaves heavy and light items in every worker: the per-worker times become 1223–1335 ms, λ = 1.036 and T_wall falls to 1366.3 ms, 1.59× faster than block-static with the same number of processes and no synchronisation at all. The total active time under cyclic/dynamic scheduling is ≈12.8 s for 1.6 × 10⁸ inner iterations (≈80 ns per sin·cos·sqrt iteration with ten processes competing for the package).

**Dynamic chunk sweep.** Results for the shared-counter queue (mp.Value('i') with its lock):

| C | 1 | 4 | 16 | 64 | 256 | 1024 |
|---|---|---|---|---|---|---|
| T_wall (ms) | 1365.3 | 1370.2 | 1376.9 | 1381.7 | 1645.9 | 1933.7 |
| λ | 1.007 | 1.008 | 1.017 | 1.047 | 1.165 | 1.851 |
| chunks claimed in total | 12000 | 3000 | 750 | 188 | 47 | 12 |

*Small C.* C = 1 gives the best balance of the whole experiment (λ = 1.007, every worker within 1291–1276 ms) and the lowest wall time, 1365.3 ms with an IQR of only 1.3 ms. The synchronisation side of the trade-off is real but tiny here: 12 000 lock acquisitions on one shared counter, each costing a few microseconds of semaphore traffic plus the invalidation of the counter's cache line between cores, add up to a few tens of milliseconds spread over ten workers, below the IQR of the measurement. The reason is the granularity of the work items: the average item costs ≈1.07 ms (12.8 s / 12 000) and the heaviest one ≈3.2 ms, three orders of magnitude more than a lock round-trip. Had the items been microsecond-sized, C = 1 would have serialised all workers on the counter.

*Large C.* With C = 1024 there are only 12 chunks for 10 workers; the eleventh chunk (items 11264–11999) alone holds 17.3 % of all the work, so whoever claims it finishes ≈0.6 s after everybody else (worker times range from 151 ms to 1840 ms, λ = 1.851) and T_wall rises by 42 % to 1933.7 ms, worse than cyclic-static. C = 256 (47 chunks, last chunk ≈5.5 % of the work) already costs +20 % (1645.9 ms, λ = 1.165). Between C = 1 and C = 64 the differences (1365–1382 ms) are within noise, so on this CPU any chunk size up to ≈64 works and **C\* = 1** is the measured optimum. A chunk of 64 items is where the tail-skew term starts to be visible (λ = 1.047), because the last chunks then contain items worth ≈3 ms each × 64 ≈ 0.2 s.

**Summary.** T_wall(block static) = 2172.8 ms, T_wall(dynamic, C\* = 1) = 1365.3 ms: dynamic scheduling removes the 59 % penalty of static partitioning on a skewed loop, and because the items are coarse-grained the cheapest possible chunk is also the best one. All wall times include ≈90 ms of process spawn/join (ten `spawn`-mode workers), which is the same for all strategies.

from dataclasses import dataclass
import multiprocessing as mp
import time
from typing import Callable


@dataclass
class BenchStats:
    min_ms: float
    median_ms: float
    iqr_ms: float
    max_ms: float


def fnv1a_hash(s: str) -> int:
    h = 14695981039346656037
    for b in s.encode("utf-8"):
        h ^= b
        h = (h * 1099511628211) & 0xFFFFFFFFFFFFFFFF
    return h


def run_benchmark(fn: Callable[[], None], warmup_runs: int = 3, timed_runs: int = 9) -> BenchStats:
    for _ in range(warmup_runs):
        fn()
    samples = []
    for _ in range(timed_runs):
        t0 = time.perf_counter_ns()
        fn()
        t1 = time.perf_counter_ns()
        samples.append((t1 - t0) / 1e6)
    samples.sort()
    mid = timed_runs // 2
    med = samples[mid] if timed_runs % 2 == 1 else 0.5 * (samples[mid - 1] + samples[mid])
    q25 = samples[timed_runs // 4]
    q75 = samples[(3 * timed_runs) // 4]
    return BenchStats(samples[0], med, q75 - q25, samples[-1])


def emit_verify_tag(task_id: str, student_seed: int,
                    primary_metric: float, secondary_metric: float) -> str:
    hw = mp.cpu_count()
    payload = (
        f"{task_id}|{student_seed}|{hw}|"
        f"{primary_metric:.4f}|{secondary_metric:.4f}"
    )
    sig = fnv1a_hash(payload)
    return f"VERIFY_HASH[{task_id}]: {sig:016X} (P_log={hw})"

        return None

    if platform.system() == "Darwin":

    """Split range(n) into `parts` contiguous (start, end) ranges, sizes differing by at most 1."""
    base, extra = divmod(n, parts)
    bounds = []
    start = 0
    for t in range(parts):
        end = start + base + (1 if t < extra else 0)
        bounds.append((start, end))
        start = end
    return bounds

    ordered = sorted(values)
    n = len(ordered)
    mid = n // 2
    return ordered[mid] if n % 2 else 0.5 * (ordered[mid - 1] + ordered[mid])

def doubling_up_to(limit: int):
    """[1, 2, 4, ..., limit] — powers of two below limit, then limit itself."""
    values = []
    p = 1
    while p < limit:
        values.append(p)
        p *= 2
    values.append(limit)
    return values

from harness import run_benchmark, emit_verify_tag

WORD_BYTES = 8


def attach(name: str) -> shared_memory.SharedMemory:
    try:
        return shared_memory.SharedMemory(name=name, track=False)
    except TypeError:  # Python < 3.13 has no track= argument
        return shared_memory.SharedMemory(name=name)


def fs_worker(shm_name: str, slot_idx: int, iters: int) -> None:
    shm = attach(shm_name)
    arr = (ctypes.c_uint64 * SLOTS).from_buffer(shm.buf)
    acc = arr[slot_idx]
    mask = 0xFFFFFFFFFFFFFFFF
    mult = 6364136223846793005
    for i in range(iters):
        acc = (acc * mult + (i | 1)) & mask
        arr[slot_idx] = acc  # direct hardware store to the shared L1 cache line
    del arr  # release buffer export before closing SharedMemory
    shm.close()


def run_trial(shm_name: str, p: int, stride: int, m_total: int) -> None:
    iters = m_total // p
    procs = [mp.Process(target=fs_worker, args=(shm_name, t * stride, iters))
             for t in range(p)]
    for proc in procs:
        proc.start()
    for proc in procs:
        proc.join()


def slot_values(shm, p: int, stride: int):
    arr = (ctypes.c_uint64 * SLOTS).from_buffer(shm.buf)
    values = [arr[t * stride] for t in range(p)]
    del arr
    return values


def bench(shm, p: int, stride: int, m_total: int, warmup: int, timed: int) -> dict:

    return (1.0 / speedup - 1.0 / p) / (1.0 - 1.0 / p)

"""Phase 2: strong (Amdahl) vs weak (Gustafson) scaling with a serial Stage A and a
Pool-parallel Stage B (task2_scaling.py)."""
import math
import multiprocessing as mp
import time

from harness import run_benchmark, emit_verify_tag
from labutil import (build_parser, resolve_student_id, results_dir, save_json,
                     hardware_info, partition, median)

N_STRONG = 1_600_000
N0_WEAK = 250_000
SERIAL_FRACTION = 0.05
STAGE_B_ITERS = 35
WARMUP, TIMED = 2, 7


def stage_a(n_serial: int) -> float:
    """Strictly serial prefix reduction: 12 transcendental ops (6 sin + 6 sqrt) per element."""
    sin, sqrt = math.sin, math.sqrt
    acc = 0.0
    for i in range(n_serial):
        x = 0.5 + (i & 1023) * 1e-3
        x = sqrt(sin(x) + 1.5)
        x = sqrt(sin(x) + 1.5)
        x = sqrt(sin(x) + 1.5)
        x = sqrt(sin(x) + 1.5)
        x = sqrt(sin(x) + 1.5)
        x = sqrt(sin(x) + 1.5)
        acc += x
    return acc


def stage_b_chunk(bounds) -> float:
    """Embarrassingly parallel kernel: 35 multiply-add + sin iterations per element."""
    start, end = bounds
    sin = math.sin
    a, b = 1.0000001, 1e-3
    acc = 0.0
    for i in range(start, end):
        x = 0.5 + (i & 1023) * 1e-3
        for _ in range(STAGE_B_ITERS):
            x = sin(x) * a + b
        acc += x
    return acc


def run_trial(pool, p: int, n: int, record: list) -> None:
    t0 = time.perf_counter_ns()
    serial_sum = stage_a(int(SERIAL_FRACTION * n))
    t1 = time.perf_counter_ns()
    partial = pool.map(stage_b_chunk, partition(n, p), chunksize=1)
    t2 = time.perf_counter_ns()
    record.append(((t1 - t0) / 1e6, (t2 - t1) / 1e6, serial_sum + sum(partial)))


def sweep(label: str, p_values, n_for_p, warmup: int, timed: int):
    rows = []
    for p in p_values:
        n = n_for_p(p)
        record = []
        with mp.Pool(processes=p) as pool:  # created outside the timed region
            stats = run_benchmark(lambda: run_trial(pool, p, n, record),
                                  warmup_runs=warmup, timed_runs=timed)
        timed_records = record[-timed:]
        row = {"p": p, "n": n, "min_ms": stats.min_ms, "median_ms": stats.median_ms,
               "iqr_ms": stats.iqr_ms, "max_ms": stats.max_ms,
               "stage_a_ms": median(r[0] for r in timed_records),
               "stage_b_ms": median(r[1] for r in timed_records),
               "checksum": timed_records[-1][2]}
        rows.append(row)
        print(f"[{label}] p={p:2d} N={n:>9}: T={row['median_ms']:9.2f} ms "
              f"(iqr {row['iqr_ms']:.2f})  stageA={row['stage_a_ms']:.2f} ms "
              f"stageB={row['stage_b_ms']:.2f} ms  sum={row['checksum']:.6f}")
    return rows


def add_strong_metrics(rows):
    t1 = rows[0]["median_ms"]
    s = rows[0]["stage_a_ms"] / t1
    prev_speedup = None
    for row in rows:
        p = row["p"]
        row["speedup"] = t1 / row["median_ms"]
        row["efficiency"] = row["speedup"] / p
        row["amdahl_speedup"] = 1.0 / (s + (1.0 - s) / p)
        row["marginal_speedup"] = None if prev_speedup is None else row["speedup"] - prev_speedup
        prev_speedup = row["speedup"]
    return {"serial_fraction_s": s, "amdahl_s_inf": 1.0 / s}


def add_weak_metrics(rows):
    t1 = rows[0]["median_ms"]
    for row in rows:
        p = row["p"]
        row["weak_efficiency"] = t1 / row["median_ms"]
        row["alpha"] = row["stage_a_ms"] / row["median_ms"]
        row["gustafson_speedup"] = p - row["alpha"] * (p - 1)


def print_strong(rows, summary):
    print(f"\nTable 2A — strong scaling, N={rows[0]['n']}  "
          f"s={summary['serial_fraction_s']:.4f}  S_inf=1/s={summary['amdahl_s_inf']:.2f}")
    print(f"{'p':>3} {'T_ms':>10} {'iqr':>7} {'S_p':>7} {'E_p':>7} {'Amdahl':>7} {'dS':>7}")
    for r in rows:
        ds = "-" if r["marginal_speedup"] is None else f"{r['marginal_speedup']:.3f}"
        print(f"{r['p']:>3} {r['median_ms']:>10.2f} {r['iqr_ms']:>7.2f} {r['speedup']:>7.3f} "
              f"{r['efficiency']:>7.3f} {r['amdahl_speedup']:>7.3f} {ds:>7}")


def print_weak(rows):
    print("\nTable 2B — weak scaling, N(p) = p * N0")
    print(f"{'p':>3} {'N':>9} {'T_ms':>10} {'iqr':>7} {'E_weak':>7} {'alpha':>7} {'S_G':>7}")
    for r in rows:
        print(f"{r['p']:>3} {r['n']:>9} {r['median_ms']:>10.2f} {r['iqr_ms']:>7.2f} "
              f"{r['weak_efficiency']:>7.3f} {r['alpha']:>7.4f} {r['gustafson_speedup']:>7.3f}")


def main() -> None:
    args = build_parser(__doc__).parse_args()
    sid = resolve_student_id(args.id)
    hw = hardware_info()
    p_phys, p_log = hw["physical_cores"], hw["logical_threads"]

    n_strong = N_STRONG // 100 if args.quick else N_STRONG
    n0_weak = N0_WEAK // 100 if args.quick else N0_WEAK
    warmup, timed = (1, 3) if args.quick else (WARMUP, TIMED)
    p_values = [1, 2, 3] if args.quick else list(range(1, p_log + 1))

    print(f"=== PHASE 2: scaling  P_phys={p_phys} P_log={p_log} warmup={warmup} timed={timed} ===")
    strong = sweep("2A strong", p_values, lambda p: n_strong, warmup, timed)
    summary = add_strong_metrics(strong)
    print_strong(strong, summary)

    weak = sweep("2B weak", p_values, lambda p: p * n0_weak, warmup, timed)
    add_weak_metrics(weak)
    print_weak(weak)

    s_strong_plog = strong[-1]["speedup"]
    s_gust_plog = weak[-1]["gustafson_speedup"]
    summary["amdahl_speedup_at_plog"] = strong[-1]["amdahl_speedup"]
    summary["observed_strong_speedup_at_plog"] = s_strong_plog
    summary["gustafson_speedup_at_plog"] = s_gust_plog
    tag = emit_verify_tag("PHASE2", sid, s_strong_plog, s_gust_plog)
    print("\n" + tag)
    save_json(results_dir(args.quick) / "phase2.json", {
        "student_id": sid, "p_phys": p_phys, "p_log": p_log,
        "n_strong": n_strong, "n0_weak": n0_weak, "warmup_runs": warmup, "timed_runs": timed,
        "strong": strong, "weak": weak, "summary": summary,
        "verify": tag, "hash_inputs": {"primary": s_strong_plog, "secondary": s_gust_plog},
    })


if __name__ == "__main__":
    main()

def bw_worker(name_a, name_b, start, end, reps, barrier, out_med_ms, out_t0, out_t1, idx) -> None:
    shm_a, shm_b = attach(name_a), attach(name_b)
    buf_a, buf_b = shm_a.buf, shm_b.buf
    buf_a[start:end] = buf_b[start:end]  # warm-up: fault pages in before timing
    barrier.wait()
    samples = []
    t_first = time.perf_counter_ns()
    for _ in range(reps):
        t0 = time.perf_counter_ns()
        buf_a[start:end] = buf_b[start:end]  # native memcpy of this worker's slice
        t1 = time.perf_counter_ns()
        samples.append((t1 - t0) / 1e6)
    out_med_ms[idx] = median(samples)
    out_t0[idx], out_t1[idx] = t_first, t1
    del buf_a, buf_b
    shm_a.close()
    shm_b.close()


def fma_worker(iters, barrier, out_t0, out_t1, out_sum, idx) -> None:
    a, b = 0.9999999, 1e-7
    x0, x1, x2, x3 = 1.0, 1.1, 1.2, 1.3
    x4, x5, x6, x7 = 1.4, 1.5, 1.6, 1.7
    x8, x9, x10, x11 = 1.8, 1.9, 2.0, 2.1
    x12, x13, x14, x15 = 2.2, 2.3, 2.4, 2.5
    barrier.wait()
    t0 = time.perf_counter_ns()
    for _ in range(iters):
        x0 = x0 * a + b
        x1 = x1 * a + b
        x2 = x2 * a + b
        x3 = x3 * a + b
        x4 = x4 * a + b
        x5 = x5 * a + b
        x6 = x6 * a + b
        x7 = x7 * a + b
        x8 = x8 * a + b
        x9 = x9 * a + b
        x10 = x10 * a + b
        x11 = x11 * a + b
        x12 = x12 * a + b
        x13 = x13 * a + b
        x14 = x14 * a + b
        x15 = x15 * a + b
    t1 = time.perf_counter_ns()
    out_t0[idx], out_t1[idx] = t0, t1
    out_sum[idx] = (x0 + x1 + x2 + x3 + x4 + x5 + x6 + x7
                    + x8 + x9 + x10 + x11 + x12 + x13 + x14 + x15)


def measure_bandwidth(p: int, buf_bytes: int, reps: int) -> dict:
    shm_a = shared_memory.SharedMemory(create=True, size=buf_bytes)
    shm_b = shared_memory.SharedMemory(create=True, size=buf_bytes)
    try:
        pattern = bytes(range(256)) * (buf_bytes // 256) + bytes(range(buf_bytes % 256))
        # macOS rounds the mapping up to a 16 KB page, so slice to the requested size
        shm_b.buf[:buf_bytes] = pattern
        shm_a.buf[:buf_bytes] = b"\x00" * buf_bytes
        del pattern
        barrier = mp.Barrier(p)
        out = mp.Array("d", p)
        t0s, t1s = mp.Array("q", p), mp.Array("q", p)
        procs = [mp.Process(target=bw_worker,
                            args=(shm_a.name, shm_b.name, s, e, reps, barrier, out, t0s, t1s, idx))
                 for idx, (s, e) in enumerate(partition(buf_bytes, p))]
        for proc in procs:
            proc.start()
        for proc in procs:
            proc.join()
        copy_ok = (bytes(shm_a.buf[:4096]) == bytes(shm_b.buf[:4096])
                   and bytes(shm_a.buf[buf_bytes - 4096:buf_bytes])
                   == bytes(shm_b.buf[buf_bytes - 4096:buf_bytes]))
        per_worker = list(out)
        t_med_ms = median(per_worker)
        bw_gbs = 2 * buf_bytes / (t_med_ms * 1e-3) / 1e9  # lab formula: assumes full overlap
        wall_ns = max(t1s) - min(t0s)                    # all reps of all workers, first start -> last end
        bw_wall_gbs = 2 * buf_bytes * reps / wall_ns     # bytes per ns == GB/s
        return {"t_median_worker_ms": t_med_ms, "per_worker_ms": per_worker,
                "bw_gbs": bw_gbs, "wall_ms": wall_ns / 1e6, "bw_wallclock_gbs": bw_wall_gbs,
                "copy_verified": copy_ok}
    finally:
        shm_a.close()
        shm_a.unlink()
        shm_b.close()
        shm_b.unlink()


def measure_compute(p: int, flops_per_worker: int) -> dict:
    iters = flops_per_worker // (2 * UNROLL)
    flops_each = iters * 2 * UNROLL
    barrier = mp.Barrier(p)
    t0s, t1s = mp.Array("q", p), mp.Array("q", p)
    sums = mp.Array("d", p)
    procs = [mp.Process(target=fma_worker, args=(iters, barrier, t0s, t1s, sums, idx))
             for idx in range(p)]
    for proc in procs:
        proc.start()
    for proc in procs:
        proc.join()
    wall_ns = max(t1s) - min(t0s)
    per_worker_gflops = [flops_each / (t1 - t0) for t0, t1 in zip(t0s, t1s)]
    return {"iters_per_worker": iters, "flops_per_worker": flops_each,
            "total_flops": p * flops_each, "wall_ms": wall_ns / 1e6,
            "gflops_aggregate": p * flops_each / wall_ns,
            "per_worker_gflops": per_worker_gflops,
            "per_worker_ms": [(t1 - t0) / 1e6 for t0, t1 in zip(t0s, t1s)],
            "checksum": sum(sums)}


def main() -> None:
    args = build_parser(__doc__).parse_args()
    sid = resolve_student_id(args.id)
    hw = hardware_info()

    buf_bytes = BUF_BYTES // 10 if args.quick else BUF_BYTES

"""Phase 3B: progressive parallel GEMM (naive i-j-k, reordered i-k-j, 6-loop blocked)
over flat array('d') buffers in SharedMemory, with a 10-point tile sweep (task3b_gemm.py)."""
import multiprocessing as mp
import random
from array import array
from multiprocessing import shared_memory

from harness import run_benchmark, emit_verify_tag
from labutil import (build_parser, resolve_student_id, results_dir, save_json,
                     hardware_info, partition)

N = 384
TILE_SIZES = [4, 8, 12, 16, 24, 32, 48, 64, 96, 128]
WARMUP, TIMED = 2, 7
SEED = 20261113
DOUBLE = 8

_A = None   # local array('d') copy of A in each pool worker
_B = None   # local array('d') copy of B in each pool worker
_C = None   # SharedMemory handle for C in each pool worker


def attach(name: str) -> shared_memory.SharedMemory:
    try:
        return shared_memory.SharedMemory(name=name, track=False)
    except TypeError:
        return shared_memory.SharedMemory(name=name)


def init_worker(name_a: str, name_b: str, name_c: str, nbytes: int) -> None:
    global _A, _B, _C
    shm_a, shm_b = attach(name_a), attach(name_b)
    _A = array("d")
    _A.frombytes(shm_a.buf[:nbytes])  # mapping may be page-rounded on macOS
    _B = array("d")
    _B.frombytes(shm_b.buf[:nbytes])
    shm_a.close()
    shm_b.close()
    _C = attach(name_c)


def store_rows(row_start: int, row_end: int, n: int, values) -> None:
    data = values if isinstance(values, array) else array("d", values)
    _C.buf[row_start * n * DOUBLE:row_end * n * DOUBLE] = data.tobytes()


def gemm_naive(task) -> None:
    """Variant 1: i-j-k, B traversed with stride N, inline index arithmetic."""
    row_start, row_end, n = task
    A, B = _A, _B
    out = []
    for i in range(row_start, row_end):
        for j in range(n):
            dot = 0.0
            for k in range(n):
                dot += A[i * n + k] * B[k * n + j]
            out.append(dot)
    store_rows(row_start, row_end, n, out)


def gemm_ikj(task) -> None:
    """Variant 2: i-k-j, a_ik hoisted, unit-stride row slices of B and C."""
    row_start, row_end, n = task
    A, B = _A, _B
    b_rows = [B[k * n:(k + 1) * n] for k in range(n)]
    out = array("d")
    for i in range(row_start, row_end):
        c_row = [0.0] * n
        base = i * n
        for k in range(n):
            a_ik = A[base + k]
            b_row = b_rows[k]
            for j in range(n):
                c_row[j] += a_ik * b_row[j]
        out.extend(c_row)
    store_rows(row_start, row_end, n, out)


def gemm_blocked(task) -> None:
    """Variant 3: 6-loop BSxBS blocking, micro-kernel order (i,k,j) with a_ik hoisted."""
    row_start, row_end, n, bs = task
    A, B = _A, _B
    c_local = [0.0] * ((row_end - row_start) * n)
    for ii in range(row_start, row_end, bs):
        i_end = min(ii + bs, row_end)
        for jj in range(0, n, bs):
            j_end = min(jj + bs, n)
            for kk in range(0, n, bs):
                k_end = min(kk + bs, n)
                for i in range(ii, i_end):
                    c_off = (i - row_start) * n
                    a_off = i * n
                    for k in range(kk, k_end):
                        a_ik = A[a_off + k]
                        b_off = k * n
                        for j in range(jj, j_end):
                            c_local[c_off + j] += a_ik * B[b_off + j]
    store_rows(row_start, row_end, n, c_local)


def make_matrix(n: int, rng: random.Random) -> array:
    return array("d", (rng.random() for _ in range(n * n)))


def read_c(shm_c, nbytes: int) -> array:
    data = array("d")
    data.frombytes(shm_c.buf[:nbytes])
    return data


def max_abs_diff(x: array, y: array) -> float:
    return max(abs(a - b) for a, b in zip(x, y))


def gflops(n: int, median_ms: float) -> float:
    return 2.0 * n ** 3 / (median_ms * 1e6)


def bench_variant(pool, fn, tasks, n, warmup, timed, label):
    stats = run_benchmark(lambda: pool.map(fn, tasks, chunksize=1),
                          warmup_runs=warmup, timed_runs=timed)
    row = {"variant": label, "min_ms": stats.min_ms, "median_ms": stats.median_ms,
           "iqr_ms": stats.iqr_ms, "max_ms": stats.max_ms, "gflops": gflops(n, stats.median_ms)}
    print(f"[{label:>10}] med={stats.median_ms:9.2f} ms iqr={stats.iqr_ms:7.2f} "
          f"-> {row['gflops']:.4f} GFLOP/s")
    return row


def main() -> None:
    args = build_parser(__doc__).parse_args()
    sid = resolve_student_id(args.id)
    hw = hardware_info()
    p_phys = hw["physical_cores"]
    n = 96 if args.quick else N
    tiles = [4, 16, 32] if args.quick else TILE_SIZES
    warmup, timed = (1, 3) if args.quick else (WARMUP, TIMED)

    rng = random.Random(SEED)
    a_mat, b_mat = make_matrix(n, rng), make_matrix(n, rng)
    nbytes = n * n * DOUBLE
    shm_a = shared_memory.SharedMemory(create=True, size=nbytes)
    shm_b = shared_memory.SharedMemory(create=True, size=nbytes)
    shm_c = shared_memory.SharedMemory(create=True, size=nbytes)
    print(f"=== PHASE 3B: GEMM N={n}  footprint={3 * nbytes / 1e6:.2f} MB  P_phys={p_phys} "
          f"warmup={warmup} timed={timed} ===")

    row_ranges = partition(n, p_phys)
    tasks_plain = [(s, e, n) for s, e in row_ranges]
    rows, checks = [], {}
    try:
        shm_a.buf[:nbytes] = a_mat.tobytes()
        shm_b.buf[:nbytes] = b_mat.tobytes()
        with mp.Pool(processes=p_phys, initializer=init_worker,
                     initargs=(shm_a.name, shm_b.name, shm_c.name, nbytes)) as pool:
            pool.map(gemm_ikj, tasks_plain, chunksize=1)
            c_ref = read_c(shm_c, nbytes)
            pool.map(gemm_naive, tasks_plain, chunksize=1)
            checks["max_abs_diff_v1_vs_v2"] = max_abs_diff(read_c(shm_c, nbytes), c_ref)
            pool.map(gemm_blocked, [(s, e, n, 16) for s, e in row_ranges], chunksize=1)
            checks["max_abs_diff_v3_bs16_vs_v2"] = max_abs_diff(read_c(shm_c, nbytes), c_ref)
            checks["c_checksum"] = sum(c_ref)
            print(f"numerical check: max|C1-C2|={checks['max_abs_diff_v1_vs_v2']:.3e}  "
                  f"max|C3(BS=16)-C2|={checks['max_abs_diff_v3_bs16_vs_v2']:.3e}  "
                  f"sum(C)={checks['c_checksum']:.6f}")

            rows.append(bench_variant(pool, gemm_naive, tasks_plain, n, warmup, timed, "V1 ijk"))
            rows.append(bench_variant(pool, gemm_ikj, tasks_plain, n, warmup, timed, "V2 ikj"))
            for bs in tiles:
                tasks = [(s, e, n, bs) for s, e in row_ranges]
                row = bench_variant(pool, gemm_blocked, tasks, n, warmup, timed, f"V3 BS={bs}")
                row["bs"] = bs
                row["tile_footprint_bytes"] = 3 * bs * bs * DOUBLE
                row["intensity_flop_per_byte"] = bs / 12.0
                rows.append(row)
    finally:
        for shm in (shm_a, shm_b, shm_c):
            shm.close()
            shm.unlink()

    v3_rows = [r for r in rows if "bs" in r]
    best = max(v3_rows, key=lambda r: r["gflops"])
    v1 = rows[0]
    print(f"\nbest tile BS*={best['bs']} -> {best['gflops']:.4f} GFLOP/s "
          f"(footprint {best['tile_footprint_bytes']} B);  V1={v1['gflops']:.4f}  "
          f"V2={rows[1]['gflops']:.4f} GFLOP/s")
    tag = emit_verify_tag("PHASE3", sid, v1["gflops"], best["gflops"])
    print("\n" + tag)
    save_json(results_dir(args.quick) / "phase3b.json", {
        "student_id": sid, "p_phys": p_phys, "n": n, "footprint_bytes": 3 * nbytes,
        "warmup_runs": warmup, "timed_runs": timed, "row_ranges": row_ranges,
        "checks": checks, "rows": rows, "best_bs": best["bs"],
        "verify": tag, "hash_inputs": {"primary": v1["gflops"], "secondary": best["gflops"]},
    })


if __name__ == "__main__":
    main()

"""Phase 4: skewed triangular workload under block-static, cyclic-static and shared-counter
dynamic chunk scheduling, with per-worker load-imbalance telemetry (task4_scheduling.py)."""
import math
import multiprocessing as mp
import time

from harness import run_benchmark, emit_verify_tag
from labutil import (build_parser, resolve_student_id, results_dir, save_json,
                     hardware_info, median)

N_ITEMS = 12_000
CHUNK_SIZES = [1, 4, 16, 64, 256, 1024]
WARMUP, TIMED = 1, 5


def work_item(i: int) -> float:
    """K(i) = 1 + floor((i/60)^2) heavy sin/cos/sqrt iterations (exact integer form)."""
    k = 1 + (i * i) // 3600
    sin, cos, sqrt = math.sin, math.cos, math.sqrt
    x = 0.5 + (i % 97) * 0.01
    for _ in range(k):
        x = sqrt(1.0 + sin(x) * cos(x))
    return x


def block_worker(t, p, n, times, sums) -> None:
    t0 = time.perf_counter_ns()
    acc = 0.0
    for i in range(t * n // p, (t + 1) * n // p):
        acc += work_item(i)
    times[t] = (time.perf_counter_ns() - t0) / 1e6
    sums[t] = acc


def cyclic_worker(t, p, n, times, sums) -> None:
    t0 = time.perf_counter_ns()
    acc = 0.0
    for i in range(t, n, p):
        acc += work_item(i)
    times[t] = (time.perf_counter_ns() - t0) / 1e6
    sums[t] = acc


def dynamic_worker(t, n, chunk, counter, times, sums, claims) -> None:
    t0 = time.perf_counter_ns()
    acc = 0.0
    n_claims = 0
    lock = counter.get_lock()
    while True:
        with lock:
            start = counter.value
            counter.value = start + chunk
        if start >= n:
            break
        n_claims += 1
        for i in range(start, min(start + chunk, n)):
            acc += work_item(i)
    times[t] = (time.perf_counter_ns() - t0) / 1e6
    sums[t] = acc
    claims[t] = n_claims


def run_static(target, p, n, times, sums) -> None:
    procs = [mp.Process(target=target, args=(t, p, n, times, sums)) for t in range(p)]
    for proc in procs:
        proc.start()
    for proc in procs:
        proc.join()


def run_dynamic(p, n, chunk, counter, times, sums, claims) -> None:
    counter.value = 0
    procs = [mp.Process(target=dynamic_worker, args=(t, n, chunk, counter, times, sums, claims))
             for t in range(p)]
    for proc in procs:
        proc.start()
    for proc in procs:
        proc.join()


def imbalance(worker_ms) -> float:
    return max(worker_ms) / (sum(worker_ms) / len(worker_ms))


def bench_strategy(label, run_fn, p, times, sums, warmup, timed, extra=None) -> dict:
    snapshots = []

    def trial() -> None:
        run_fn()
        snapshots.append(list(times))

    stats = run_benchmark(trial, warmup_runs=warmup, timed_runs=timed)
    timed_snaps = snapshots[-timed:]
    lambdas = [imbalance(s) for s in timed_snaps]
    row = {"strategy": label, "min_ms": stats.min_ms, "median_ms": stats.median_ms,
           "iqr_ms": stats.iqr_ms, "max_ms": stats.max_ms,
           "lambda_median": median(lambdas), "lambda_runs": lambdas,
           "worker_ms_last": timed_snaps[-1],
           "worker_ms_max": max(timed_snaps[-1]), "worker_ms_mean": sum(timed_snaps[-1]) / p,
           "checksum": sum(sums)}
    if extra:
        row.update(extra)
    print(f"[{label:>16}] T_wall med={stats.median_ms:9.1f} ms iqr={stats.iqr_ms:7.1f}  "
          f"lambda={row['lambda_median']:.3f}  "
          f"workers(ms)=" + " ".join(f"{t:.0f}" for t in timed_snaps[-1]))
    return row


def main() -> None:
    args = build_parser(__doc__).parse_args()
    sid = resolve_student_id(args.id)
    hw = hardware_info()
    p = hw["physical_cores"]
    n = N_ITEMS // 10 if args.quick else N_ITEMS
    chunks = [1, 64, 1024] if args.quick else CHUNK_SIZES
    warmup, timed = (1, 1) if args.quick else (WARMUP, TIMED)
    total_iters = sum(1 + (i * i) // 3600 for i in range(n))

    print(f"=== PHASE 4: scheduling  N={n}  p={p}  total inner iterations={total_iters}  "
          f"K(0)={1}  K(N-1)={1 + (n - 1) ** 2 // 3600}  warmup={warmup} timed={timed} ===")
    times, sums = mp.Array("d", p), mp.Array("d", p)
    claims = mp.Array("i", p)
    counter = mp.Value("i", 0)

    rows = [bench_strategy("S1 block static", lambda: run_static(block_worker, p, n, times, sums),
                           p, times, sums, warmup, timed),
            bench_strategy("S2 cyclic static", lambda: run_static(cyclic_worker, p, n, times, sums),
                           p, times, sums, warmup, timed)]
    for chunk in chunks:
        row = bench_strategy(f"S3 dynamic C={chunk}",
                             lambda: run_dynamic(p, n, chunk, counter, times, sums, claims),
                             p, times, sums, warmup, timed, extra={"chunk": chunk})
        row["claims_per_worker_last"] = list(claims)
        rows.append(row)

    dynamic_rows = [r for r in rows if "chunk" in r]
    best = min(dynamic_rows, key=lambda r: r["median_ms"])
    print(f"\nC* = {best['chunk']}  (T_wall {best['median_ms']:.1f} ms, lambda {best['lambda_median']:.3f})")
    tag = emit_verify_tag("PHASE4", sid, rows[0]["median_ms"], best["median_ms"])
    print("\n" + tag)
    save_json(results_dir(args.quick) / "phase4.json", {
        "student_id": sid, "p": p, "n": n, "total_inner_iterations": total_iters,
        "warmup_runs": warmup, "timed_runs": timed, "rows": rows, "best_chunk": best["chunk"],
        "verify": tag, "hash_inputs": {"primary": rows[0]["median_ms"], "secondary": best["median_ms"]},
    })


if __name__ == "__main__":
    main()

"""Self-audit: recompute every VERIFY_HASH line from the saved metrics exactly the way the
